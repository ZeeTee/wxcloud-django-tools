## 0. 一分钟结论（先看这段）

| 问题 | 结论 |
|---|---|
| 云托管 vs 云开发 | 两套独立产品，两套独立控制台，环境互不可见。云托管=容器（任意语言），云开发=云函数（Node.js） |
| 云托管必须配云开发吗 | **不需要**。`callContainer` 的 `config.env` 填的是**云托管环境ID**，跟云开发环境无关 |
| 小程序调用方式 | `wx.cloud.callContainer`，基础库 **≥ 2.23.0**，`header` 里必须带 `X-WX-SERVICE` |
| 需要配服务器域名吗 | **不需要**（官方明确 callContainer 免域名校验），也不用备案 |
| callContainer 超时上限 | **15 秒**（SDK 参数上限）；平台级请求最大超时 **60 秒** |
| LLM 改写 10–60 秒能直连吗 | **不能**。必须改异步任务 + 轮询，或走 WebSocket（`connectContainer`），或走自定义域名公网 |
| callContainer 支持 SSE 吗 | **不支持**（社区官方回答：走公网域名才可能） |
| Django 端口 | 容器内监听 `0.0.0.0:80`（或任意 1–61000 非 9100 的端口），**必须与控制台填写端口一致** |
| 官方 Django 模板能直接上生产吗 | **不能**。模板用 `runserver` + `DEBUG=True` + 硬编码 SECRET_KEY，是 demo |
| 停止服务还收费吗 | 最小副本=0 且 30 分钟无请求 → 缩容到 0 → 不再产生容器费用；但数据库存储一直收费 |

## 1. 微信云托管 与 微信云开发（CloudBase）的区别

### 1.1 是不是同一个东西？

**不是。** 🟢 官方原文：

> 微信云开发和微信云托管都是微信联合腾讯云打造的微信云服务生态的组成部分……
> 微信云开发以**云函数**提供计算能力，围绕 **Node.js** 技术栈，适合前端开发者简单快捷实现后端功能；
> 微信云托管以**容器**提供计算能力，**支持任意后端语言和框架**，适合前后端分离项目的后端开发、传统模式后端项目迁移。

来源：[常见问题 · 基本概念](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/info/faq.html)

同一页还明确了三件容易踩坑的事（🟢）：

1. **旧的「云开发里的云托管」模块已停止功能更新**，仅支持存量业务运行，建议迁移到微信云托管。
2. **微信云托管的环境在「微信开发者工具的云开发控制台」里看不到** —— 两套独立体系。
3. **微信云托管的环境在「腾讯云控制台」里也看不到** —— 只能在微信云托管控制台管理。
4. **必须先有微信小程序/公众号才能开通微信云托管**；但部署上去的服务可以开公网被 APP/网站调用（只是失去 callContainer 的内网链路优势）。

### 1.2 云托管必须配合「云开发环境」使用吗？

**不必须，而且两者不通用。** 🟢 官方在 Python 快速入门里写得很直白：

```js
wx.cloud.init({
  // env: "其他云开发环境，也可以不填" // 此处init的环境ID和微信云托管没有作用关系，没用就留空
});
const res = await wx.cloud.callContainer({
  config: {
    env: "微信云托管ID", // 微信云托管环境ID，不能为空，替换自己的
  },
  path: '/',
  method: 'GET',
  header: { 'X-WX-SERVICE': 'demo' }
});
```

来源：[快速入门 - Python 自定义部署](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/quickstart/custom/python.html)

关键区别（🟢）：

| | `wx.cloud.init({env})` | `callContainer({config:{env}})` |
|---|---|---|
| env 含义 | 云开发环境 ID | **微信云托管环境 ID** |
| 是否必填 | 可不填、可填任意环境 | **必填，不能为空** |
| 是否影响云托管调用 | **不影响** | 决定打到哪个云托管环境 |

⚠️ 一个**命名坑**：云托管与云开发「共用同一个腾讯云账号」（如果小程序开通过云开发）。但这只是计费主体层面的复用，不代表环境通用。

来源：[环境创建和管理](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/env/)（原文：「如果你之前在某个「小程序/公众号」中开通过云开发，则会与其共用一个腾讯云账号……所以在这种情况下，可以实现微信云托管的资源和云开发的资源在内网联通（前提是要配置相同的 VPC）」）

### 1.3 小程序端怎么调用？

- **微信体系内（推荐）**：`wx.cloud.callContainer` —— 走微信内网链路，带用户身份 header，免域名，免 DDoS。
- **公网**：直接请求服务公网域名 / 自定义域名 —— 不带任何微信用户信息，需要自己做登录鉴权。

🟢 官方对「可信任调用方」的界定（重要安全结论）：

> 请注意，并非任何人、任何小程序/公众号只要能拿到环境 id 和服务名，就能任意调用对应的云托管服务。云托管的安全性保证了只有以下小程序/公众号可以通过 callcontainer 内网访问对应的服务：
> 1. 当前小程序/公众号直接开通的微信云托管环境；
> 2. 同一主体的其他小程序/公众号开通的微信云托管环境，并在微信云托管控制台为当前小程序/公众号设置了「资源复用」。

来源：[调用服务问题排查指引](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/call/faq.html)

「资源复用」的用法（同主体多小程序共享一个后端，🟢）：

```js
const c1 = new wx.cloud.Cloud({
  resourceAppid: 'WXAAA', // 环境所属的账号 AppID
  resourceEnv: 'prod_001', // 微信云托管的环境ID
})
await c1.init()
await c1.callContainer({
  config: { env: 'prod_001' },
  path: '/xxx',
  method: 'POST',
  header: { 'X-WX-SERVICE': 'xxx' }
})
```

来源：[资源复用](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/reuse/)

## 2. 小程序端调用云托管服务的确切 API

### 2.1 `wx.cloud.callContainer` 完整参数

🟢 官方参数表（[微信小程序 - 访问云托管服务](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/call/mini.html)）：

| 属性 | 类型 | 默认值 | 必填 | 说明 |
|---|---|---|---|---|
| `config.env` | string | — | **是** | 微信云托管**环境 ID**（不是环境名） |
| `path` | string | — | **是** | 后端服务接口地址，根目录就是 `/` |
| `data` | string / object / ArrayBuffer | — | 否 | 请求参数 |
| `header` | Object | — | **是** | 请求 header，**不能设置 Referer**；`content-type` 默认 `application/json`；**必须含 `X-WX-SERVICE`** |
| `timeout` | number | — | 否 | 毫秒。**最大值不能超过 15 秒，否则无效** |
| `method` | string | `GET` | 否 | `OPTIONS`/`GET`/`HEAD`/`POST`/`PUT`/`DELETE`/`TRACE`/`CONNECT` |
| `dataType` | string | `json` | 否 | `json` 或「其他」（其他则不 JSON.parse） |
| `responseType` | string | `text` | 否 | `text` / `arraybuffer` |
| `success`/`fail`/`complete` | function | — | 否 | ⚠️ **想拿 Promise 就不要传这三个** |

返回值（🟢 来自 [SDK 参考 · Cloud.callContainer](https://developers.weixin.qq.com/minigame/dev/wxcloud/reference-sdk-api/container/Cloud.callContainer.html)）：

| 属性 | 类型 | 说明 |
|---|---|---|
| `data` | string / Object / ArrayBuffer | 服务返回数据（`dataType:'json'` 时已 parse） |
| `statusCode` | number | HTTP 状态码 |
| `header` | Object | 响应 header |
| `cookies` | Object | 响应 cookies（字符串数组，**仅小程序端有**，Web 端没有） |

> 注意 `errMsg` 和 `callID` 在官方示例代码里被打印（`result.errMsg | callid:${result.callID}`），但**没有出现在参数/返回值表里**。可视为实际存在但未正式文档化。

### 2.2 真实可运行的示例代码

**app.js（一次性 init + 万能封装）** 🟢 官方推荐写法（略作整理）：

```js
// app.js
App({
  cloud: null,

  async onLaunch() {
    // 使用 callContainer 前一定要 init，全局执行一次即可
    // init 的 env 与云托管无关，可留空
    wx.cloud.init({ traceUser: true })
  },

  /**
   * 微信云托管调用封装：同时兼容「自己的小程序」和「资源复用」两种形态
   * @param {Object} obj  { path, method, data, header, dataType, timeout }
   * @param {Number} number 内部重试计数，业务不要传
   */
  async call(obj, number = 0) {
    const that = this
    if (that.cloud == null) {
      const cloud = new wx.cloud.Cloud({
        // 自己小程序直属的环境：resourceAppid 可以不传
        // 资源复用场景：resourceAppid 填「环境所属账号」的 AppID
        // resourceAppid: 'WXAAA',
        resourceEnv: 'prod-001', // ← 微信云托管的环境ID
      })
      that.cloud = cloud
      await that.cloud.init() // init 是异步的，必须 await
    }
    try {
      const result = await that.cloud.callContainer({
        config: { env: 'prod-001' },   // ← 云托管环境ID，必填
        path: obj.path,
        method: obj.method || 'GET',
        data: obj.data,
        dataType: obj.dataType,        // 非 JSON 返回时传 'text'
        timeout: obj.timeout,          // 注意：≤ 15000
        header: {
          'X-WX-SERVICE': 'django-api', // ← 服务名（控制台-服务管理-服务列表-服务名称）
          ...(obj.header || {}),
        },
      })
      console.log(`调用结果 ${result.errMsg} | callid:${result.callID}`)
      return result.data
    } catch (e) {
      const error = e.toString()
      // init 异步竞态：未初始化时等 300ms 重试
      if (error.indexOf("Cloud API isn't enabled") !== -1 && number < 3) {
        return new Promise((resolve) => {
          setTimeout(() => resolve(that.call(obj, number + 1)), 300)
        })
      }
      throw new Error(`微信云托管调用失败: ${error}`)
    }
  },
})
```

**页面里调用**：

```js
const app = getApp()
Page({
  async onLoad() {
    const data = await app.call({
      path: '/api/rewrite',       // 对应 Django 的 URL
      method: 'POST',
      data: { text: '要改写的文本' },
      timeout: 15000,             // 单位 ms，绝不要超过 15000
    })
    console.log(data)
  },
})
```

**注意中文乱码**：🟢 官方 FAQ 明确 ——

> 请求通过 callContainer 传到后台 params 出现中文乱码 → 解决方法：自行做下 `encodeURIComponent`。

来源：[调用服务问题排查指引](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/call/faq.html)。实际建议是 **body 用 JSON 传**（默认 content-type 就是 json，一般不会有问题），而 **query string 里的中文必须 `encodeURIComponent`**。

### 2.3 调用前必须 `wx.cloud.init` 吗？env 填什么？

- 🟢 **必须 init**，但只需全局一次（`onLaunch`）。官方注释：`// 使用callContainer前一定要init一下，全局执行一次即可`。
- 🟢 **`wx.cloud.init()` 的 env 与云托管无关**，「任意环境均可，可以填空」。
- 🟢 **真正决定打到哪个云托管环境的是 `callContainer` 里的 `config.env`**，必须填**云托管环境ID**（不是环境名）。
- 🟢 `new wx.cloud.Cloud({resourceEnv})` 的 `init()` 是**异步**的，必须 `await`，否则会报 `Cloud API isn't enabled`（官方示例代码里就是用 try/catch + 300ms 重试兜住的）。

相关错误码（🟢 官方 FAQ）：

| errCode | 含义 | 处理 |
|---|---|---|
| `-601027` | `Environment not found` | 环境 ID 填错。**注意不是环境名** |
| `-601031` | `EnvDbId [], ServiceName [] not exist` | 服务名/环境ID 错，或环境不属于当前小程序，或只有一个空服务没有线上版本 |
| `-601034` | `没有权限，请先开通云托管` | 当前小程序未开通，也没被同主体「资源复用」 |
| `-501000` | `Authorization mismatch uin` / `Path access permission error` | 忘了配 `resourceAppid`，或 path 格式有问题 |
| `-606001` | 请求包 > 100KB | 压缩请求体；图片/文件先传对象存储，只传 fileID |
| `-606002` | 响应包 > 1MB | 同上 |
| `102002` | 请求超时 | 见 §2.6 |
| `102005` | 无效 HTTP Method | 只用 GET/POST/PUT/DELETE 等合法值 |

### 2.4 app.json / 小程序后台需要配置什么？

**结论：不需要配置服务器域名。** 🟢 三条官方原文：

1. callContainer 的**优势**之一：「**无需在小程序后台配置「服务器域名」**」（[微信小程序-访问云托管服务](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/call/mini.html)）
2. 「小程序/公众号可使用 CallContainer，**无需域名**，因此不需要在 mp 管理后台配置服务器域名，从而一开始就无需申请域名，也无需备案。」（[开发常识](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/debug/know.html)）
3. 小程序框架文档：「如使用微信云托管作为后端服务，则可**无需配置通讯域名**（在小程序内通过 callContainer 和 connectContainer 通过微信私有协议向云托管服务发起 HTTPS 调用和 WebSocket 通信）。」（[网络](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)）

**唯一必须做的小程序后台配置**（🟢，且缺一不可）：

> 前往「小程序管理后台」-「设置」-「功能设置」-「基础库最低版本设置」，将值设定为 **2.23.0** 及以上。

来源：[微信小程序-访问云托管服务](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/call/mini.html)、[恶意攻击应对指南](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/scene/noun/ddos.html)

`app.json` 里可选项（🟢 小程序框架文档）：

```json
{
  "networkTimeout": {
    "request": 60000
  }
}
```

> ⚠️ `networkTimeout.request` 是否作用于 callContainer，**官方未说明**。已知 callContainer 自身 `timeout` 参数上限 15s，优先级更高。

⚠️ **不需要**在 `app.json` 里加 `cloud: true` / `cloudfunctionRoot` 之类（那是云开发的云函数配置，与云托管无关）。

### 2.5 与传统 `wx.request` 的区别和取舍

🟢 官方列出的 callContainer 优势（[原文](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/call/mini.html)）：

1. 不耗费任何公网流量，前后端通信走内网；
2. 天然免疫 DDoS 攻击，仅授权小程序/公众号可访问后端，其他人即便拿到环境 id 和服务名也无法访问；
3. 通过微信就近接入节点加速，无视后端服务地域影响，没有跨地域延迟，后端无需多地部署；
4. **无需在小程序后台配置「服务器域名」**；
5. 后端可直接获取用户信息，无需调接口即可以获取 openid 等。

| 维度 | `wx.cloud.callContainer` | `wx.request` 走公网域名 |
|---|---|---|
| 用户身份 | 🟢 自动带 `X-WX-OPENID` 等，**免鉴权** | ❌ 无，必须自己做登录态 |
| 域名/备案 | 🟢 不需要 | ❌ 需 ICP 备案域名 + 控制台配置 + HTTPS 证书 |
| 默认公网域名 | — | ❌ **不能**配进小程序后台（官方明确） |
| 超时上限 | 🟢 15s（`timeout` 参数） | 🟢 默认 60s，可配 |
| SSE / 流式 | ❌ 不支持 | 🟡 可（chunked/SSE），但要自定义域名 |
| DDoS | 🟢 免疫 | ❌ 不免疫 |
| 计费 | 🟢 不产生公网流量费 | ❌ 产生公网流量费（0.8 元/GB） |
| 适用前端 | 仅小程序 / 已登录公众号 H5 | 任意客户端 |

> 🟢 官方建议：「因此，如果云托管服务**只有**微信小程序/公众号会调用，建议在服务设置中**关闭公网访问**。」

### 2.6 超时上限与长耗时（LLM 改写 10–60 秒）怎么办

**这是本笔记最重要的工程结论。**

**硬上限（🟢）：**

| 层级 | 上限 | 来源 |
|---|---|---|
| `callContainer` 的 `timeout` 参数 | **15 秒**（「最大值不能超过 15 秒，否则无效」） | [调用服务 FAQ](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/call/faq.html)、[开发常识](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/debug/know.html) |
| 平台级「请求最大超时时间」 | **60 秒** | [调用云托管服务](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/call/) |
| 请求体 / 响应体 | 100 KiB / 1000 KiB（二进制 20 MiB） | 同上 |

⚠️ **文档冲突**：[SDK 参考页](https://developers.weixin.qq.com/minigame/dev/wxcloud/reference-sdk-api/container/Cloud.callContainer.html) 写的是「本项取值需要小于 **1500 毫秒**（服务启动耗时＋请求耗时 < timeout < 1500 毫秒）」。这与「15 秒」三处官方文档+FAQ 矛盾，**判断为 SDK 参考页的历史遗留错误**。工程上按 **15s** 处理，并且**不要依赖接近 15s 的边界**。

**结论：10–60 秒的 LLM 改写，callContainer 直连做不到。** 官方原话（🟢）：

> 普通请求耗时过长（非冷启动）时，建议采用**异步方式**，将请求耗时压缩到所设 timeout 之内。

**官方唯一给出的处方 = 异步任务。** 具体做法（Django 侧）：

```
POST /api/rewrite        → 立即返回 { task_id }，耗时 < 1s
GET  /api/rewrite/{id}   → 前端每秒轮询，返回 { status: pending|done|failed, result }
```

但异步有**官方点名的三个坑**（🟢 [异步任务场景使用指南](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/scene/noun/async.html)）：

1. **最小副本=0（低成本模式）**：半小时无请求就缩容到 0，**你的后台线程会随容器一起被杀**。
2. **最小副本=1（高可用模式）**：如果流量高峰扩到了 2 个实例，之后缩容回 1，**恰好在你任务所在那个实例上，任务就夭折了**。
3. 因此官方建议：「**尽量在请求响应前完成异步操作**」；如果非要跑长任务，需要每 15 分钟发请求「守护」住容器，并把扩缩容阈值设到 >95% 降低扩容概率。

另外一条**小程序框架级硬约束**（🟢 [网络](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)）：

> 小程序进入后台运行后，如果 **5s** 内网络请求没有结束，会回调错误信息 `fail interrupted`；在回到前台之前，网络请求接口调用都会无法调用。

**这意味着即使用户在小程序里等 30 秒，只要他切出去看别的，请求必死。** 这是「必须异步 + 轮询」的第二个硬理由。

**长耗时的三条可行路线（按推荐度）：**

| 方案 | 可行性 | 说明 |
|---|---|---|
| **① 异步任务 + 轮询** | 🟢 官方推荐 | 每次轮询 < 1s，天然躲过 15s。后端用 DB/Redis 存任务状态。**容器最小副本建议设 1**，并把长任务交给「不会被缩容」的机制 |
| **② WebSocket（`connectContainer`）** | 🟢 官方支持 | 基础库 **≥ 2.21.1**，只能 `wss`。可做流式推送。可绕过 15s HTTP 限制 |
| **③ 公网自定义域名 + `wx.request` + SSE/chunked** | 🟡 社区方案 | callContainer **不支持 SSE**，社区官方回答明确要求「走云托管提供的公网域名，通过 http 协议访问」。代价：需备案域名、需配小程序服务器域名、产生公网流量费、暴露公网被攻击风险 |

**关于 SSE —— 社区（微信开放社区）回答原文（🟡）：**

> 「callContainer 由于使用了微信的特定链路，**不支持 SSE 协议返回**。如果要使用 SSE，建议走云托管提供的公网域名，通过 http 协议访问」

来源：[云托管的API以Streaming方式获取大语言模型数据，如何以流媒体方式返回前端？](https://developers.weixin.qq.com/community/minihome/doc/00082245d50dd89520b11bd0b6b400)（提问者实测：callContainer 会等所有流数据都拿到才返回给前端）

**`connectContainer` 官方示例**（🟢 [WebSocket-微信小程序](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/websocket/miniprogram.html)）：

```js
App({
  onLaunch: async function () {
    wx.cloud.init({ traceUser: true })
    const { socketTask } = await wx.cloud.connectContainer({
      config: { env: 'wxrun-demo' }, // 云托管环境ID
      service: 'ws',                 // 服务名
      path: '/'                      // 不填默认根目录
    })
    socketTask.onMessage(res => console.log('【WEBSOCKET】', res.data))
    socketTask.onOpen(() => {
      console.log('【WEBSOCKET】链接成功！')
      socketTask.send({ data: '这是小程序消息' })
    })
    socketTask.onClose(() => console.log('【WEBSOCKET】链接关闭！'))
  }
})
```

⚠️ 已知限制（🟢）：**iOS 高性能+ 模式下，`connectContainer` 暂时无法携带微信身份**（服务端读不到 `x-wx-openid`）。WebSocket 服务端还需要过滤健康检查连接（带 `Connection: Upgrade` / `Upgrade: websocket` 的才是真连接）。

**冷启动与 102002 超时的关系**（🟢）：如果服务在自动暂停后冷启动，冷启动耗时也会算进你的 timeout。官方解决方式是「实例副本数最小值设为 1」保持常驻（会产生费用）。

### 3.3 生产可用的 Dockerfile（本项目推荐）

```dockerfile
# ---------- 生产可用 Django Dockerfile（微信云托管） ----------
FROM python:3.11-slim

# 时区（云托管容器默认 UTC，日志时间会差 8 小时）
ENV TZ=Asia/Shanghai \
    PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1

RUN apt-get update && apt-get install -y --no-install-recommends \
        tzdata ca-certificates \
    && ln -snf /usr/share/zoneinfo/$TZ /etc/localtime && echo $TZ > /etc/timezone \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

# 先装依赖，最大化利用构建缓存
COPY requirements.txt .
RUN pip config set global.index-url https://mirrors.cloud.tencent.com/pypi/simple \
 && pip config set global.trusted-host mirrors.cloud.tencent.com \
 && pip install --no-cache-dir -r requirements.txt

COPY . .

# collectstatic：把 admin 等静态资源收进 STATIC_ROOT
# 注意：构建阶段没有环境变量、也连不上内网 MySQL，所以这里只做不需要 DB 的事
RUN python manage.py collectstatic --noinput

# 端口必须与控制台「服务设置/发布时」填写的端口完全一致
EXPOSE 80

# 单行 CMD；多行独立 CMD 只有最后一行生效（官方 FAQ 明确）
# --timeout 建议 <= 平台 60s 上限，且给异步任务留余量
CMD ["sh", "-c", "gunicorn wxcloudrun.wsgi:application \
  -b 0.0.0.0:80 \
  -w 2 -k gthread --threads 4 \
  --timeout 55 --graceful-timeout 30 --keep-alive 5 \
  --access-logfile - --error-logfile -"]
```

🟢 **关于 `gunicorn` 的说明**：微信云托管官方文档**没有**指定 Django 的生产 WSGI 服务器（模板用 `runserver`）。`gunicorn` 是 🟡 Django 官方文档与社区通用做法，不是微信云托管的规定。

关键点（🟢）：
- **只支持一个端口**，且**不能是 9100**，范围 1–61000。默认 80。
- **端口必须与控制台填写的端口一致，否则部署失败**（官方 FAQ `Readiness probe failed: dial tcp ... connection refused`）。
- **多行独立 CMD 只有最后一行生效**（官方 FAQ 明确列为常见错误）。
- `EXPOSE` 只是声明，云托管通过控制台填写的端口做 TCP 探测。

来源：[开发常识](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/debug/know.html)、[概念解释](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/basic/noun.html)、[服务问题排查指引](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/service/faq.html)

### 3.4 `container.config.json` 完整字段含义

⚠️ **最重要的一句话（🟢 官方模板文件头注释原文）：**

> ```
> // 本配置文件仅配合模板部署使用，为模板部署的服务生成「服务设置」的初始值。
> // 模板部署结束后，后续服务发布与本配置文件完全无关，修改「服务设置」请到控制台操作。
> // 复制模板代码自行开发请忽略本配置文件。
> ```

**也就是说**：`container.config.json` **只在「控制台一键模板部署」那一次生效**。你如果自己新建服务 + 上传代码包 / 绑 Git 仓库，**这个文件会被忽略，端口/规格/环境变量都要在控制台手填**。

🟢 [Django 模板 container.config.json 原文](https://github.com/WeixinCloud/wxcloudrun-django/blob/main/container.config.json)：

```jsonc
{
	// 本配置文件仅配合模板部署使用，为模板部署的服务生成「服务设置」的初始值。
	// 模板部署结束后，后续服务发布与本配置文件完全无关，修改「服务设置」请到控制台操作。
	// 复制模板代码自行开发请忽略本配置文件。

	"containerPort": 80,                           // 容器监听端口（必须与 Dockerfile EXPOSE 一致）
	"minNum": 0,                                   // 最小副本数：0=低成本(30min 无请求缩容到 0)，>=1=常驻无冷启动
	"maxNum": 5,                                   // 最大副本数（费用上限的硬闸门）
	"cpu": 1,                                      // CPU 核数
	"mem": 2,                                      // 内存 GB
	"policyType": "cpu",                           // 扩缩容判定指标：cpu | mem
	"policyThreshold": 60,                         // 触发扩缩容的使用率阈值(%)
	"policyDetails": [                             // 多条件扩缩容（注意字段名是大驼峰）
		{ "PolicyType": "cpu", "PolicyThreshold": 60 },
		{ "PolicyType": "mem", "PolicyThreshold": 60 }
	],
	"envParams": {},                               // 环境变量 { "KEY": "VALUE" }
	"customLogs": "stdout",                        // 日志采集路径，默认 stdout；可多个用半角逗号分隔
	"initialDelaySeconds": 2,                      // 启动延迟探测，避免启动慢被误判失败
	"dataBaseName": "django_demo",                 // 仅模板部署：自动开通 MySQL 时建的库
	"executeSQLs": [                               // 仅模板部署：自动执行的建库建表 SQL
		"CREATE DATABASE IF NOT EXISTS django_demo;",
		"USE django_demo;",
		"CREATE TABLE IF NOT EXISTS `Counters` (...) ENGINE = InnoDB DEFAULT CHARSET = utf8;"
	]
}
```

字段逐项解释（🟢 结合 [服务设置](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/service/pipeline.html)、[概念解释](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/basic/noun.html)、[本地调试](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/debug/)）：

| 字段 | 控制台对应位置 | 含义与约束 |
|---|---|---|
| `containerPort` | 发布时填的「端口」 | **只支持 1 个端口**；1–61000 且 ≠ 9100；默认 80；必须与 Dockerfile 一致，否则 `Readiness probe failed` |
| `minNum` | 服务设置 → 实例副本数（最小） | `0` = 无流量时 30 分钟后缩容到 0（0 成本，有冷启动）；`≥1` = 常驻（无冷启动，持续计费） |
| `maxNum` | 服务设置 → 实例副本数（最大） | ⚠️ **费用上限的唯一闸门**，务必设小 |
| `cpu` / `mem` | 服务设置 → 容器规格 | 必须按配对表：`0.25/0.5`、`0.5/1`、`1/2`、`2/4`、`4/8`、`8/16`、`16/32` |
| `policyType` + `policyThreshold` | 服务设置 → 扩缩容条件 | 支持 CPU 使用率、内存使用率；默认 60%。官方建议：**内存消耗 > CPU 的服务用 mem 做条件**（否则 CPU 没达标但内存已满） |
| `policyDetails` | 同上 | 多条件版；⚠️ 字段名大小写是 `PolicyType`/`PolicyThreshold`（与顶层 `policyType` 不一致） |
| `envParams` | 服务设置 → 环境变量 | 注入容器 `os.environ`；⚠️ **构建阶段读不到**（官方 FAQ：「构建/部署阶段，服务还未就绪，此时无法引用环境变量」） |
| `customLogs` | 服务设置 → 日志采集路径 | 默认 `stdout`；支持 `/logs/*` 通配；**不能与 Dockerfile 的 volume 路径相同**，否则二次映射采不到 |
| `initialDelaySeconds` | — | 启动延迟，避免启动慢被健康检查误判 |
| `dataBaseName` / `executeSQLs` | — | **仅模板部署**用于自动开通 MySQL 并执行初始化 SQL |

⚠️ **未找到「健康检查路径（health check path）」配置项的权威来源。**
微信云托管官方文档中**没有**暴露 HTTP 健康检查路径字段；从错误信息 `Readiness probe failed: dial tcp xx.xx.xx.xx:xxx: connect: connection refused` 看，**健康检查是 TCP 端口级探测**，不是 HTTP 路径探测。唯一相关的可配项是 `initialDelaySeconds`。

**现代替代方案 —— CLI 的 `wxcloud.config.js`**（🟢 [项目配置](https://cloud.weixin.qq.com/cli/features/config.html)）：

```json
{
  "type": "run",
  "server": {
    "port": 80,
    "buildDir": ".",
    "versionRemark": "django-api"
  }
}
```

`server` 字段（🟢）：`port`（默认 80）、`buildDir`（默认 `.`）、`versionRemark`（默认 `cloudkit`）。
`type` 取值：`universal`（全栈混合）/ `static`（前端静态）/ `run`（纯后端云托管）/ `custom`。
CLI 部署命令（🟢）：`wxcloud deploy -e <环境ID> -s <服务名> -p <端口>`。

### 3.5 Django 侧的硬性要求

#### (1) `ALLOWED_HOSTS` 怎么设

🟢 官方模板当前写法（[settings.py](https://github.com/WeixinCloud/wxcloudrun-django/blob/main/wxcloudrun/settings.py)）：

```python
ALLOWED_HOSTS = ['*']
```

**建议写法**（🟡 基于 Django 官方行为 + 云托管网关事实）：

```python
import os

# 云托管的 Host 头由统一网关转发，可能是默认公网域名或内网域名，域名不固定
# 用环境变量注入，本地默认放宽
ALLOWED_HOSTS = os.environ.get('DJANGO_ALLOWED_HOSTS', '*').split(',')

# DEBUG=False 时 ALLOWED_HOSTS 不能为空，否则所有请求 400
```

要点：
- `DEBUG = False` 时 **`ALLOWED_HOSTS` 为空会让 Django 直接返回 400**，这是最经典的部署翻车点。
- 🟢 云托管网关会把请求转发到你的端口，**公网域名/自定义域名/内网域名都可能成为 Host 头**，所以设成 `['*']` 是最省事且被官方模板采用的做法。若要走白名单，需把**默认公网域名、自定义域名、内网域名**都列上。
- ⚠️ 官方文档**没有**对 Django `ALLOWED_HOSTS` 给过专门建议（因为云托管语言无关）。上面的白名单做法是 🟡 社区/框架惯例。

#### (2) 监听 host/port

```python
# 必须监听 0.0.0.0，不能是 127.0.0.1
# 端口必须与控制台填写的端口一致（默认 80）
```

- 🟢 官方示例统一 `host='0.0.0.0'`、`port=int(os.environ.get('PORT', 80))`。
- 🟢 **只支持一个端口**；需要多端口 → 拆成多个服务。
- 🟢 官方环境变量表里只有 `CBR_ENV_ID`、`MYSQL_USERNAME`、`MYSQL_PASSWORD`、`MYSQL_ADDRESS`。
  ⚠️ **推断（未找到权威来源）**：`PORT` **不在**官方文档列出的注入变量里，所以 `os.environ.get('PORT', 80)`（官方 Flask 示例的写法）大概率永远拿到 80。**结论：不要指望平台告诉你端口，必须让 Dockerfile/Gunicorn 的端口与控制台手填值硬对齐。**

自定义环境变量相关（🟢 [容器内变量信息](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/weixin/)）：

| 变量 | 说明 |
|---|---|
| `CBR_ENV_ID` | 当前环境 ID |
| `MYSQL_USERNAME` | 模板部署自动开通数据库时的用户名 |
| `MYSQL_PASSWORD` | 同上，密码 |
| `MYSQL_ADDRESS` | 同上，数据库**内网地址**（`ip:port` 格式） |

> 🟢 官方明确：如果不是用模板部署自动开通的 MySQL，这三个变量**不会自动产生**，要自己在「服务设置 → 环境变量」里补。

#### (3) static 文件怎么处理

🟢 事实约束：
- **容器不支持持久化存储**，重启/扩缩容后写入的文件被还原。
- 反复强调：**静态资源强烈建议放「静态资源存储」**，不要放容器里（放容器会导致公网流量费暴涨、被刷风险高）。
- 云托管默认**没有 nginx**，Django 自己在 `DEBUG=False` 下**不服务 static**。

🟡 因此三选一：

**方案 A（推荐，最简单）：Whitenoise**
```python
MIDDLEWARE = [
    # ... 必须放在 SecurityMiddleware 之后
    'whitenoise.middleware.WhiteNoiseMiddleware',
    'django.middleware.security.SecurityMiddleware',
    # ...
]
STATIC_URL = '/static/'
STATIC_ROOT = BASE_DIR / 'staticfiles'
STORAGES = {
    "staticfiles": {"BACKEND": "whitenoise.storage.CompressedManifestStaticFilesStorage"},
}
```
+ Dockerfile 里 `RUN python manage.py collectstatic --noinput`
+ `requirements.txt` 加 `whitenoise`

**方案 B：反代自己起 nginx**（多进程管理麻烦，不推荐）

**方案 C（官方最推荐，前端资源）：静态资源存储 / 对象存储**
🟢 官方定位：静态资源存储有默认域名 + CDN + 缓存配置 + 防盗链 + IP 黑白名单 + 限频 + CORS。

**关键区分**：这里说的 static 是 **Django admin / DRF 静态文件**。而**小程序前端根本不在云托管里**（小程序包本身是上传到微信平台的），所以「前端静态资源」通常指公众号 H5 / Web 页面。

#### (4) DEBUG 必须关闭吗

🟢 **必须。** 理由：
- `DEBUG=True` 会返回完整堆栈、SQL、settings 片段，**严重信息泄露**。
- `DEBUG=True` 时 Django 会用开发用的 static serve，行为与生产不一致。
- 🟢 官方模板把它设为 `True` 只是为了方便 demo（注释原文：`# SECURITY WARNING: don't run with debug turned on in production!`）。

生产 settings 关键片段（建议直接照抄）：


#### (5) migration 怎么执行

🟢 官方专门写了一篇 [Django 部署云托管使用 migration](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/scene/noun/migration.html)，给了 4 种方式并逐一点评：

| 方式 | 官方评价 |
|---|---|
| ① Dockerfile 里 `RUN` 执行 migrate | ❌ 不推荐。**构建环境不在数据库 VPC 内网**，只能用外网地址；且拖长构建耗时 |
| ② 本机连数据库**外网地址**执行 | 简单，但**新版服务未就位就改表结构可能引发线上故障** |
| ③ 启动时在 CMD/ENTRYPOINT 里执行 | ⚠️ 可用，但注意：**多实例同时创建会有竞争**（要加锁）；migration 要短；过程长的要有「升级中」兜底 |
| ④ 进 WebShell 手动执行 | ✅ 推荐（安全考虑不想开外网地址时）。WebShell 实例在数据库 VPC 内网 |

**推荐落地（方式③ + 防竞争）**：

```sh
#!/bin/sh
# start.sh
set -e
# 用一个 DB 行锁 / advisory lock 保证只有 1 个实例迁移
python manage.py migrate --noinput
exec gunicorn wxcloudrun.wsgi:application -b 0.0.0.0:80 -w 2 -k gthread --threads 4 --timeout 55
```

```dockerfile
CMD ["sh", "start.sh"]
```

> 🟢 提醒：`MYSQL_ADDRESS` 是**内网地址**，只能在容器运行时（同 VPC）访问，构建阶段访问不到。所以 `migrate` **绝对不能**放在 `RUN` 里。

**「服务名」「环境ID」在哪里获取**（🟢）：

| 值 | 位置 |
|---|---|
| **环境 ID** | 「设置 → 环境设置 → 基础信息」；或容器内 `os.getenv('CBR_ENV_ID')`。⚠️ **不是环境名**（环境名后面被追加了随机串才是 ID） |
| **服务名** | 「服务管理 → 服务列表 → 服务名称」。**创建后不支持修改**。这就是 `X-WX-SERVICE` 的值 |

**其他关键机制（🟢）**：
- **版本配置锁定**：版本创建时的规格/副本数/扩缩容条件/环境变量会**锁定在版本里**。改配置会**自动触发一个新版本**。
- **旧版本缓存 2 分钟**：新版本发布后旧版本还会活 2 分钟，期间部分请求可能打到旧版本。
- **回退只能向前**（高版本 → 低版本）。
- **上线前必须先本地 Docker 跑通**（官方：「正式部署之前，请确保服务在本地 Docker 可以正常运行，否则线上部署一定会有问题」）。
- **推送触发**只能全量发布现网；删了 webhook 就失效。
- 微信云托管**不支持**：Docker Compose、WAF、一个服务多端口、公网 IP 直连、tcp/udp/mqtt、部署有状态服务（DB/Redis）。

## 4. 鉴权与安全

### 4.1 服务端如何拿到调用者身份？是否可信？

🟢 从小程序/已登录 Web 端发起的请求，容器内 header 含（[容器内变量信息](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/weixin/)）：

| header | 说明 |
|---|---|
| `X-WX-OPENID` | 小程序用户 OpenID。**资源复用情况下不存在**，见 `X-WX-FROM-OPENID` |
| `X-WX-APPID` | 小程序 AppID |
| `X-WX-UNIONID` | 用户 UnionID（满足 UnionID 获取条件时才有） |
| `X-WX-FROM-OPENID` | **资源复用**情况下，小程序用户 OpenID |
| `X-WX-FROM-APPID` | 资源复用情况下，使用方小程序 AppID |
| `X-WX-FROM-UNIONID` | 资源复用情况下，小程序用户 UnionID |
| `X-WX-ENV` | 所在云环境 ID |
| `X-WX-SOURCE` | 调用来源（本次运行是被什么触发） |
| `X-Original-Forwarded-For` | 客户端 IPv4 或 IPv6 地址 |

**是否可信？—— 是，官方明确表态（🟢）：**

> 「此类调用包含微信用户的信息，在调用过程中经过微信链路并由微信验证了用户信息……开发者**可以完全信任这些 header 头**。」
> 「云托管免登录验证的这些信息，是由微信团队保证的，全程进行了加密处理，防刷防攻击。」

来源：[调用云托管服务](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/call/)、[云托管小程序登录流程优化](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/quickstart/plan/login.html)

**但仍需额外校验 —— 两个官方提醒（🟢）：**

1. **必须判断 `X-WX-SOURCE` 是否存在**，才能确保来源是微信生态端（小程序/公众号 H5）。原文：「请求处理时如需保证调用来源是微信生态端（微信小程序、公众号 H5），请判断 `X-WX-SOURCE` 头部是否存在」。
2. **公网访问不带任何微信信息**。如果服务开了公网，任何人都能发请求且**不带** `X-WX-*`。所以：**要么关闭公网访问，要么对公网入口做独立鉴权**。
3. **`X-WX-OPENID` 在资源复用场景下不存在**，必须 fallback 到 `X-WX-FROM-OPENID`。

**Django 侧取 header 的写法（注意框架差异，🟢 官方明确警告）：**

> 「header 是大小写不敏感的，有些框架可能会将原始 header 转为小写，甚至有些框架会强转为无划线驼峰或下划线形式，请在业务开发之前**先打印测试 header 信息**！」

```python
# Django：request.headers 是大小写不敏感的，推荐用这个
def get_wx_identity(request):
    """返回 (openid, appid, source)；非微信链路返回 (None, None, None)"""
    source = request.headers.get('X-WX-SOURCE')          # 只有微信链路才有
    openid = request.headers.get('X-WX-OPENID')          # 直属环境
    if not openid:
        openid = request.headers.get('X-WX-FROM-OPENID') # 资源复用
    appid = request.headers.get('X-WX-APPID') or request.headers.get('X-WX-FROM-APPID')
    return openid, appid, source

# 兜底：如果某些 WSGI 中间件把 header 弄成了下划线形式，也可以从 META 读
# request.META.get('HTTP_X_WX_OPENID')   # 注意是 X_WX_OPENID，不是 X-WX-OPENID
# request.META.get('HTTP_X_ORIGINAL_FORWARDED_FOR')
```

⚠️ **客户端 IP 的 header 名在两篇官方文档里不一致**：[容器内变量信息](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/weixin/) 写 `X-Original-Forwarded-For`，[登录流程优化](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/quickstart/plan/login.html) 写 `X-Forwarded-For`。**建议两个都读**，并当作参考信息，不要用作安全判据。

**推荐的鉴权中间件（本项目落地写法）：**

```python
# middleware.py
import json
from django.http import JsonResponse

class WxIdentityMiddleware:
    """
    把 X-WX-* 解析成 request.wx = {openid, appid, source, env, ip}
    非微信链路 + 未开公网 = 不可能到达，所以这里主要做「来源校验」。
    """
    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        h = request.headers
        request.wx = {
            'source': h.get('X-WX-SOURCE'),
            'openid': h.get('X-WX-OPENID') or h.get('X-WX-FROM-OPENID'),
            'appid': h.get('X-WX-APPID') or h.get('X-WX-FROM-APPID'),
            'unionid': h.get('X-WX-UNIONID') or h.get('X-WX-FROM-UNIONID'),
            'env': h.get('X-WX-ENV'),
            'ip': (h.get('X-Original-Forwarded-For')
                   or h.get('X-Forwarded-For') or '').split(',')[0].strip(),
        }
        # 业务接口强制要求来自微信生态端
        if request.path.startswith('/api/') and not request.wx['source']:
            return JsonResponse({'code': 401, 'msg': '非微信生态端调用'}, status=401)
        if request.path.startswith('/api/') and not request.wx['openid']:
            return JsonResponse({'code': 401, 'msg': '缺少用户身份'}, status=401)
        return self.get_response(request)
```

> 🟢 官方定位：**不需要 `wx.login`，也不需要 code 换 session**。「这个能力是不带任何条件的，小程序只要使用 `wx.cloud.callContainer`，云托管服务收到这个请求，信息就自然而然带入进来了。」
> 而且「不需要自己做登录态了，因为你在任意请求中都可以拿到用户的身份信息」。
> 如果你仍坚持 `auth.code2Session` 流程，「并不会有任何安全、防刷的能力提升」。

### 4.2 内网/公网访问开关，如何开通公网域名，access_token 注意事项

#### (1) 公网访问开关

🟢 「服务设置 → 基础信息 → 公网访问」：
- **关闭**后：只能被小程序 / 已登录公众号 H5 的 `callContainer` 调用（以及同环境内网服务调用）。**杜绝公网 DDoS**。
- 关闭公网访问**只限制外向内**，不限制服务内向外发请求。
- 🟢 关闭公网访问的**三条缺一不可**（[恶意攻击应对指南](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/scene/noun/ddos.html)）：
  1. 小程序前端全部用 `callContainer` 取代 `wx.request`；
  2. 控制台「服务设置」**关闭「公网访问」**；
  3. 小程序后台把「基础库最低版本」设为 **2.23.0+**。

#### (2) 公网域名

🟢 [自定义域名](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/domain/)：

- **默认公网域名**：服务创建时自动分配，形如 `https://<服务名>.<地域>.run.tcloudbase.com`。
  - 🚨 **仅作测试之用**，「容易受不同地区网络波动/运营商政策影响，不建议用于大规模生产环境」。
  - 🚨 「**小程序后台也无法配置使用默认公网域名**」（所以想走 `wx.request` 就必须绑自定义域名）。
- **自定义域名**：控制台「服务管理 → 自定义域名 → 绑定自定义域名」。
  1. 域名**必须已 ICP 备案**（否则无法访问）；
  2. 上传 HTTPS 证书（推荐 nginx 文本证书，`.crt`/`.pem` + `.key`，不支持二进制）；
  3. 去 DNS 服务商加 **CNAME** 指向云托管返回的地址；
  4. 1 个域名对应 1 个服务；1 个服务可绑多个域名。
- 微信云托管**暂未支持域名备案功能**，官方建议「另外购买服务器专门做备案之用（买最便宜的即可）」。
- 🟢 小程序/公众号纯 callContainer 场景**完全不需要域名，也不需要备案**。

#### (3) 内网调用

🟢 [服务间内网调用](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/service/internal.html)：
- 每个开启内网访问的服务会分配一个**内网域名**（开启时**自动触发一次部署发布**）。
- 内网调用**端口 = 服务部署发布时填写的端口**，其他端口不可用。
- ⚠️ **文档冲突**：[服务迁移检查清单](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/scene/change/check.html) 里写「服务间的内网访问，目前因为安全原因暂时下线，只能使用公网互相访问」。这与较新的「服务间内网调用」操作文档矛盾，**判断为旧文档未更新**，以「服务设置」控制台实际可见的开关为准。

#### (4) access_token / 微信开放接口

🟢 [云调用&微信令牌](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/weixin/token.html)：

**核心结论：不要自己维护 access_token，用「开放接口服务」（云调用）。**

- 云调用 = **免鉴权、免密钥**调用微信开放接口，开发者**无需维护 access_token**。
- 开启方式：控制台 → 云调用 → **配置接口白名单**（**环境维度**，配置后环境内所有服务生效）。
  - 白名单只填 `api.weixin.qq.com` 之后、`?` 之前的部分。例如要调 `https://api.weixin.qq.com/wxa/msg_sec_check?access_token=xxx`，白名单里填 `/wxa/msg_sec_check`。
- 🟢 **`jscode2session` 的坑（重要）**：
  > 「开启『开放接口服务』情况下，使用 `jscode2session` 会发生白名单配置错误，原因是：开放接口服务以调用是否传 `access_token` 参数判定是否走原生。因为 `jscode2session` 没有 `access_token` 参数，所以就会发生走『开放接口服务』鉴权情况。这种情景下，可以关闭『开放接口服务』然后重新部署一下自己的业务服务。」
- 🟢 因此：**如果你坚持用 `wx.login` + `code2Session`，就不要开「开放接口服务」**；纯 callContainer 方案则**根本不需要 code2Session**。
- 🟢 使用 HTTP（而非 HTTPS）调用 `api.weixin.qq.com` 是安全的：「开放接口服务在容器内进行网络交互，请求不会离开用户容器（解析到 `169.254.0.x`）」。
- 🟢 部分自带根证书的运行时需手动设置证书，路径 `/app/cert/certificate.crt`；容器需有 shell（`scratch` 基础镜像不行）。
- 🟢 老的「微信令牌 `cloudbase_access_token`」方式：**2022 年 7 月后创建的环境均不再支持**，已下线。不要再读写 `/.tencentcloudbase/wx/cloudbase_access_token`。
- 🟢 云托管**没有固定公网出口 IP**（动态变化）；需要固定 IP 要买「出口固定 IP」增值服务（49 元/月/环境，**不可用于域名备案**）。

### 5.4 Django 最小可用配置大概什么量级

- 假设每天 8:00–24:00 有流量（16 小时维持 1 个实例）：
  - 每日 CPU：0.25 × 16 = 4 核·小时 → 4 × 0.055 = 0.22 元
  - 每日内存：0.5 × 16 = 8 GB·小时 → 8 × 0.032 = 0.256 元
  - **每日 ≈ 0.476 元；每月 ≈ 14.28 元**

⚠️ **但 Django 比这个基线上限高**（Gunicorn 多 worker + Django 本体 + 框架开销）：
- 🟡 **工程量级判断（非官方）**：Django + Gunicorn 建议 **0.5 核 / 1GB** 起（0.0595 元/小时），常驻 24h 月约 **43 元**；0.25 核 / 0.5GB 可能连 1 个请求都撑不住（官方明确：规格过小会「部署成功但频繁出现 500 错误」）。
- 如果用 MySQL：加最小 0.25 CCU（约 0.0855 元/小时 ≈ 61.6 元/月）+ 存储，是主要成本项。🟢 官方建议「充分利用自动弹性伸缩」，数据库自动暂停（10 分钟无操作）后**不算力计费**。
- 如果最小副本设 1 常驻：0.5 核 1G × 730 小时 ≈ **43.4 元/月**（不含 DB、不含构建、不含流量）。

🟢 **费用上限控制手段**：
- **最大副本数**是费用硬闸门（官方：「每个版本的实例数上限为 50 个，超过上限不会再继续扩容，即每日费用上限完全可控」）。

- 告警设置里配「调用次数」+「平均实例个数」告警，防被刷。

## 6. 给实现者的清单

### 6.1 硬性约束（违反就一定出问题）

**A. 小程序侧**

1. ✅ 基础库最低版本 → 小程序后台设为 **2.23.0+**（callContainer）/ **2.21.1+**（connectContainer）。**不设就是白屏/报错**。
2. ✅ `onLaunch` 里 `wx.cloud.init()` **全局一次**，`await` 完成再发请求。
3. ✅ `callContainer` 必须传 `config.env`（**云托管环境ID，不是环境名**）和 `header['X-WX-SERVICE']`（**服务名**）。
4. ✅ `timeout` **不得超过 15000 ms**，超过则参数无效。
5. ✅ **不要传 `success`/`fail`/`complete`** —— 传了就不返回 Promise。
6. ✅ 请求体 ≤ **100 KiB**，响应体 ≤ **1000 KiB**。图片/视频先传对象存储，只传 `fileID`。
7. ✅ `header` 里**不能设置 `Referer`**。
8. ✅ query string 里的中文要 `encodeURIComponent`。
9. ✅ `method` 只用 `GET/POST/PUT/DELETE/...` 合法值（`wx.cloud.callContainer is not a function` 是基础库太低；`GET/DELETE/PUT 都变成 POST` 也是基础库太低）。
10. ❌ **不需要**在 `app.json` 配服务器域名，**不需要**备案域名。
11. ⚠️ **用户切后台 5 秒后请求必被杀**（`fail interrupted`）→ 长任务必须异步。

**B. Django 侧**

12. ✅ **必须 `ALLOWED_HOSTS` 非空**（`DEBUG=False` 下为空 → 全站 400）。官方模板用 `['*']`。
13. ✅ **`DEBUG = False`**（生产必须）。
14. ✅ `SECRET_KEY` 从环境变量读，**不要硬编码进 git**。
15. ✅ 监听 **`0.0.0.0`**，端口 **与控制台填写值完全一致**（默认 80，范围 1–61000，**不能是 9100**）。
16. ✅ **只支持一个端口**；多端口拆多服务。
17. ✅ 用 **Gunicorn**（或 uwsgi），**不要用 `runserver`**。
18. ✅ Dockerfile **只有一行 CMD**（多行只有最后一行生效）。
19. ✅ `pip` 装依赖时用国内镜像（`mirrors.cloud.tencent.com`），否则构建可能因访问国外网络失败。
20. ✅ 静态文件：`collectstatic` + Whitenoise，或放到静态资源存储。**`DEBUG=False` 下 Django 不服务 static**。
21. ✅ `migrate` **不能放在 Dockerfile 的 `RUN` 里**（构建环境不在 DB 内网）。放启动脚本 + 分布式锁（多实例竞争）。
22. ✅ 容器**不持久化**：不写文件到本地磁盘；上传文件走对象存储。
23. ✅ `CBR_ENV_ID` / `MYSQL_ADDRESS` / `MYSQL_USERNAME` / `MYSQL_PASSWORD` 是模板部署自动开通 DB 才有的；**手动开通要自己在控制台补环境变量**。
24. ✅ 环境变量**在构建阶段读不到**，只能在运行时读。
25. ✅ 时区默认 UTC，要 Asia/Shanghai 必须在 Dockerfile 里改；**无 Dockerfile 模式不能改时区**。
26. ✅ 日志打 **stdout**（默认采集路径），不要在容器里写文件当日志。

**C. 架构/安全侧**

27. ✅ 纯小程序后端 → **关闭「公网访问」**（关闭后 callContainer 仍可用）。
28. ✅ 即使 `X-WX-*` 被官方认定为可信，也**校验 `X-WX-SOURCE` 存在**，并对公网入口另做鉴权。
29. ✅ 资源复用场景要读 **`X-WX-FROM-OPENID`** 作为兜底。
30. ✅ 用 **`request.headers`**（大小写不敏感）读 header；**开发前先打印一次真实 header 验证框架没有篡改**。
31. ✅ 需要调微信开放接口 → 开「开放接口服务」+ 配白名单（**环境维度**，填 `/wxa/msg_sec_check` 这种路径）。
32. ✅ **不要自己维护 `access_token`**；不要用已下线的 `cloudbase_access_token` 文件方式。
33. ✅ 用 `jscode2session` 就**不要开**「开放接口服务」。
34. ✅ `minNum=0` → 冷启动；`minNum=1` → 常驻费用。按业务权衡。
35. ✅ **把 `maxNum` 设成你能承受的费用上限**（这是唯一的成本闸门）；配告警防刷。

### 6.2 最容易踩的坑（按踩坑概率排序）

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| 1 | 端口不一致 | 部署成功但 `Readiness probe failed: dial tcp ... connection refused` | 控制台填的端口 == Dockerfile `EXPOSE` == Gunicorn `-b 0.0.0.0:<port>` |
| 2 | `ALLOWED_HOSTS=[]` + `DEBUG=False` | 全站 400 Bad Request | `['*']` 或列全所有域名 |
| 3 | callContainer 超 15s | `errCode: 102002 请求超时` | 异步任务 + 轮询 |
| 4 | 想要流式输出 | callContainer 等全部数据才返回 | 不支持 SSE；改 WebSocket 或公网自定义域名 |
| 5 | 基础库最低版本没设 | `wx.cloud.callContainer is not a function` | 小程序后台设 2.23.0+ |
| 6 | `env` 填了环境名 | `errCode: -601027 Environment not found` | 填**环境ID** |
| 7 | 忘了 `wx.cloud.init()` 或没 `await` | `Cloud API isn't enabled` | `onLaunch` 里 init，或加重试 |
| 8 | 最小副本=0 跑长任务 | 后台任务莫名消失、接口 500 | 长任务要么 <15s 内完成，要么 minNum=1 + 守护 |
| 9 | `migrate` 放 Dockerfile `RUN` | 拉不到内网 DB，构建失败 | 放启动脚本（加锁）或 WebShell 手动跑 |
| 10 | 多实例同时 migrate | 表结构竞争报错 | 启动脚本里加 DB 锁 |
| 11 | 把图片塞进请求/响应 | `-606001` / `-606002` | 走对象存储传 `fileID` |
| 12 | 容器里写文件 | 重启后文件不见了 | 对象存储 |
| 13 | 时区差 8 小时（日志时间对不上） | 日志/DB 时间戳全错 | Dockerfile 装 tzdata + `TZ=Asia/Shanghai` |
| 14 | 日志采不到 | 控制台日志是空的 | 打 stdout；采集路径不能只到子目录；不能与 volume 路径相同 |
| 15 | `requirements.txt` 用了模板的 `powerline-status` | 无意义依赖 | 删掉 |
| 16 | Django 4.x + 模板 `url()` | `ImportError: cannot import name 'url'` | 用 `re_path`/`path` |
| 17 | 模板 settings 里 `os.environ.get("MYSQL_ADDRESS").split(':')` | 环境变量缺失时 `AttributeError` | 先判断存在性（`os.environ[...]` 让错误更清晰） |
| 18 | 上传代码包超 2 MiB | 上传失败 | 用 Git 仓库方式，或 `.dockerignore` 瘦身 |
| 19 | 开了「开放接口服务」还用 `jscode2session` | 白名单配置错误 | 关掉开放接口服务并重新部署 |
| 20 | 默认公网域名想配进小程序后台 | 配不上 | 默认域名仅测试用，线上必须绑备案的自定义域名 |
| 21 | 多行 CMD | 只有最后一行生效，服务起不来 | 合成一行或用脚本 |
| 22 | 版本配置「改了没生效」 | 以为改了配置但流量里还是旧配置 | 版本创建时锁定配置；改配置会自动发新版本，要走灰度/全量 |
| 23 | 发新版后旧版仍接流量 | 少量请求打到旧代码 | 旧版本缓存 2 分钟是设计如此；官方建议先灰度 50% 再隔 3–5 分钟结单 |
| 24 | 环境长期没流量 | 30 天无请求被冻结，180 天被销毁 | 留意告警 |
| 25 | 攻击导致费用暴涨第二天才发现 | 按天结算 | 配告警 + 调小 `maxNum` + 关公网 |

### 6.3 本项目推荐的最小可用配置

| 项 | 建议值 | 理由 |
|---|---|---|
| 容器规格 | **0.5 核 / 1GB** | Django+Gunicorn 比 Flask 重；0.25/0.5 容易 500 |
| 最小副本 | 短任务：**0**；有长任务/要求低延迟：**1** | 0 = 省钱但有冷启动；1 = 常驻约 43 元/月 |
| 最大副本 | **2 或 3** | 个人项目费用闸门 |
| 扩缩容条件 | **内存 ≥ 70%**（若内存是瓶颈）/ CPU ≥ 60% | 官方建议内存型服务用内存指标 |
| 端口 | **80** | 与 Dockerfile 一致 |
| 日志采集路径 | `stdout` | 默认值，最省事 |
| 公网访问 | **关闭**（纯小程序） | 免域名、免备案、免 DDoS |
| 长耗时 LLM 方案 | **异步任务 + 轮询**（`POST /api/rewrite` 返回 taskId，`GET /api/rewrite/<id>` 轮询） | 唯一被官方推荐的方案，且绕过 15s 限制 |
| 数据库 | 云托管 MySQL 5.7（如需） | 8.0 创建后不能改大小写敏感；注意 28M 系统表一直计费 |
| 环境数 | 1（生产），需要测试再加 | 只有第 1 个环境有免费额度 |
